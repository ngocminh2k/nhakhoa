CHƯA SẴN SÀNG DEPLOY PRODUCTION

Hệ thống có 3 lỗ hổng CRITICAL cần vá ngay trước khi lên Matbao. Hai file nhạy cảm (docker-compose.yml và .env.example) đang public, lộ credentials DB và API key. Toàn bộ CORS mở wildcard. Đây là blocker cứng.

Top 3 Việc Phải Fix Ngay

  1. Block docker-compose.yml + .env.example qua Apache

    Hai file này public hoàn toàn — lộ DB password, API key, cấu trúc stack. Fix trong .htaccess, không cần đụng PHP. Mất <2 phút.

  2. Đổi CORS từ wildcard * thành domain cụ thể

    Sửa một dòng trong backend/core/Response.php. Kết hợp với API key bị lộ, CORS wildcard cho phép bất kỳ site nào gọi API.

  3. Thêm CSP + HSTS + ẩn Server header

    Thêm vào .htaccess. HSTS bắt buộc HTTPS, CSP chặn XSS, ẩn Server header hạn chế CVE targeting.

Critical — 3 Findings

CRITICAL docker-compose.yml public — lộ toàn bộ credentials DB + API key ▾
Mô tả

GET /docker-compose.yml trả về HTTP 200. File chứa root password MariaDB (root), user password (nhakhoa_pass), AUTOMATION_API_KEY (kd_dev_test_key_abc123), và DB port 3306 mapped ra host. Attacker kết nối thẳng vào MariaDB.

File cần sửa: .htaccess
# Dòng hiện tại — THIẾU docker-compose và .example
<FilesMatch "(^\\.env|\\.git|\\.sql|\\.log|\\.lock|composer\\.(json|lock)|package(-lock)?\\.json|\\.md|google_sheets\\.json)$">
    Order allow,deny
    Deny from all
</FilesMatch>

# Thay bằng — thêm docker-compose.yml, .example, .yml, .sh, .bak, .xml
<FilesMatch "(^\\.env|docker-compose\\.ya?ml|\\.git|\\.sql|\\.log|\\.lock|composer\\.(json|lock)|package(-lock)?\\.json|\\.md|google_sheets\\.json|\\.example|\\.bak|\\.sh|\\.xml)$">
    Order allow,deny
    Deny from all
</FilesMatch>
CRITICAL .env.example public — lộ AUTOMATION_API_KEY production ▾
Mô tả

/.env.example trả về HTTP 200 và chứa AUTOMATION_API_KEY=kd_live_sec_7a8f9b2c3d4e5f6a1b2c3d4e5f6a7b8c. Pattern ^\\.env trong FilesMatch chỉ match đúng .env — không match .env.example. Fix chung với finding #1 ở trên (thêm |\\.example vào FilesMatch).

Hành động bổ sung

Sau khi block file, rotate API key ngay — key đã bị public nên coi như compromised. Tạo key mới trong DB admin, cập nhật .env thực trên server.

CRITICAL CORS wildcard Access-Control-Allow-Origin: * trên toàn bộ API ▾
Mô tả

Mọi origin kể cả https://evil.com được phép gọi API. Kết hợp với API key đã lộ, bất kỳ website độc hại nào cũng tạo được booking.

File cần sửa: backend/core/Response.php
// Dòng 13 hiện tại
header('Access-Control-Allow-Origin: *');

// Thay bằng — whitelist domain thực của clinic
$allowed = [
    'https://nhakhoakimdung.com',
    'https://www.nhakhoakimdung.com',
    // Thêm subdomain nếu cần
];
$origin = $_SERVER['HTTP_ORIGIN'] ?? '';
if (in_array($origin, $allowed, true)) {
    header("Access-Control-Allow-Origin: $origin");
    header('Vary: Origin');
} elseif ($origin === '') {
    // Same-origin request — không cần CORS header
}
// Không match: không set header → browser block cross-origin

High — 2 Findings

HIGH Server banner lộ Apache version + OS trên mọi response ▾
Mô tả

Server: Apache/2.4.68 (Debian) trong mọi response header, kể cả trang lỗi. Cho phép attacker tra CVE nhắm mục tiêu chính xác.

File cần sửa: .htaccess — thêm vào cuối
# Ẩn server version (cần ServerTokens Prod trong httpd.conf nếu có quyền)
<IfModule mod_headers.c>
    Header unset Server
    Header always unset X-Powered-By
    Header unset X-Powered-By
</IfModule>
Lưu ý

Trên Matbao shared hosting, ServerTokens Prod phải nhờ support set trong httpd.conf. Header unset Server trong .htaccess đủ để ẩn version khỏi application responses.

HIGH Method check chạy TRƯỚC auth — lộ cấu trúc route ▾
Mô tả

Server trả về 405 METHOD_NOT_ALLOWED trước khi check API key. Attacker không có key vẫn enumerate được route/method qua error codes.

File cần sửa: api/v1/bookings.php — đổi thứ tự check
// TRƯỚC: method check → rate limit → (không có auth cho bookings)
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    Response::error('METHOD_NOT_ALLOWED', '...', 405);
}
if (!RateLimiter::check('booking_submit', 10, 3600)) { ... }

// SAU: rate limit trước, rồi method check
if (!RateLimiter::check('booking_submit', 10, 3600)) {
    Response::error('RATE_LIMITED', 'Quá nhiều yêu cầu.', 429);
}
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    Response::error('INVALID_REQUEST', 'Yêu cầu không hợp lệ.', 400); // 400 thay vì 405
}

Trả về 400 thay vì 405 giảm information leakage về method expectations.

Medium — 3 Findings

MEDIUM Thiếu Content-Security-Policy và Strict-Transport-Security ▾
File cần sửa: .htaccess — bổ sung vào block headers
<IfModule mod_headers.c>
    Header set X-Content-Type-Options "nosniff"
    Header set X-Frame-Options "SAMEORIGIN"
    Header set X-XSS-Protection "1; mode=block"
    Header set Referrer-Policy "strict-origin-when-cross-origin"
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains" env=HTTPS
    Header set Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' https://fonts.gstatic.com; connect-src 'self'"
</IfModule>

Điều chỉnh CSP sau khi kiểm tra các script/style bên ngoài thực tế dùng trong template HTML.

MEDIUM SQLi / XSS / Mass Assignment chưa verify được — bị block bởi rate limit ▾
Mô tả

Toàn bộ test payload SQLi, XSS, mass assignment đều bị 429 RATE_LIMITED trước khi đến business logic. Rate limit đang hoạt động đúng — nhưng cần verify code review thủ công.

Khuyến nghị

Review backend/core/Validator.php và backend/security/Sanitizer.php để confirm: (1) parameterized queries trong tất cả Repository, (2) Sanitizer::text() escapes HTML output, (3) không có field nào inject được role/status/id vào payload.

Code hiện tại dùng PDO prepared statements và whitelist fields tường minh trong BookingService — có vẻ đúng nhưng cần audit thủ công từng Repository file.
